## Decisions made

- **Ownership hierarchy: machine → process → loop → connection.** Memory is private per process (pool connections are TCP sockets in one process's memory); DB rows are shared. Two processes never share a saver — they share checkpoint rows found by `thread_id`. (Corrected my inverted answer twice before it stuck.)
- **Option B: one long-lived loop per worker child**, saver created on it in `worker_process_init`, tasks use `_loop.run_until_complete`. Justification: pool stays warm across tasks; per-task `asyncio.run` would pay pool-open cost per run *and* can't touch a saver bound to a different loop ("attached to a different loop"). Safe because prefork children run one task at a time.
- **`worker_process_init` not `celeryd_after_setup`**: the latter fires once in the parent; prefork children fork *after*. Signals live in `celery.signals`, NOT as `celery_app` attributes (my typo'd first attempt).
- **Celery signals question resolved by reading `celery/signals.py:110` directly.**
- **`from_conn_string` returns `AsyncIterator[AsyncPostgresSaver]` via `@asynccontextmanager`** — consumed by hand-driving `__aenter__`/`__aexit__` since there is no `async with` scope that spans process lifetime.
- **Exception placement:** `app/workers/exceptions.py`, `WorkerNotInitializedError(RuntimeError)`.
- **Fail-semantics rule, sharpened:** DataFlag answers to a *state consumer*; exception answers to the *caller*. `_graph is None` at task time = no state exists → no flag possible → raise. "No state consumer, no flag."
- **Scope fence:** enumerating all managers at 6 AM is NOT #110. The task takes explicit `manager_id`/`company_ticker` args.
- **Create-vs-consume drift found:** `TriggerRequest` has `company_id`; `create_initial_state` wants `company_ticker`. Flagged for PR, not fixed here.
