## Decisions made

- **`(404, NO_ACTIVE_RUN)` is deliberately ambiguous** — the pipeline can't distinguish "run started but not live" from "run finished." No cause is asserted because no cause is known.
- **`translate()` default is LOUD** — unmapped `PipelineError` subclass logs a distinctive line + returns 500, so a missed mapping is a findable bug, not a silent 500.
- **Translator + helpers live in `errors.py`** — single responsibility for the error concern (types, translation, rendering); importable for unit tests without bootstrapping the FastAPI app.
- **RLS bypass stays 404 (`NOT_FOUND`)** — hide-existence posture (deferred ADR decision, plan line 94). Do NOT promote to 403/`RLS_VIOLATION` silently.
- **Duplicate feedback ships `CONFLICT`** — kept simple; `IDEMPOTENCY_KEY_EXISTS` exists in `ErrorCodes` but unused this pass.

## REAL BUG FOUND + FIXED (uncommitted)

- `app/main.py` `validation_handler` passed `exc.errors` (a method in this FastAPI version) instead of `exc.errors()`.
- Symptom: `TypeError: 'method' object is not iterable` **server-side** → every `RequestValidationError` (422) fell through to the generic handler → **500**.
- The 3 "422" feedback tests were MASKING this — they ran while the server 500'd and only broke when the body shape changed to `KeyError: 'detail'`.
- Fix applied: `_build_dict_of_lists(exc.errors())`. **Uncommitted** with the test edits.
