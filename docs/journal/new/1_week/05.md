### Chunk C3 — halfvec + HNSW index
- C1 created the `embedding` column as `vector(2048)`. The migration
  that tries to index it with HNSW failed with
  `column cannot have more than 2000 dimensions for hnsw index`.
  pgvector's HNSW caps at 2000 dims on `vector` (lifts to 4000 on
  `halfvec`). Per pgvector 0.8.5 README.
- Switched column type to `halfvec(2048)`. Storage halves
  (4 bytes/float → 2). Cosine distance on half-precision is fine
  for retrieval — quantizes the float values, distance math stays
  identical.
- New migration `9c3d5e7f1a23_hnsw_index_on_morning_notes_embedding_.py`
  hand-written with three DDL ops:
  1. `DROP COLUMN embedding` (drops the vector column from C1)
  2. `ADD COLUMN embedding halfvec(2048)` (replaces with halfvec)
  3. `CREATE INDEX idx_morning_notes_embedding_hnsw ON morning_notes
     USING hnsw (embedding halfvec_cosine_ops)`
- Model file updated to import `HALFVEC` from `pgvector.sqlalchemy`
  and use `HALFVEC(2048)` instead of `Vector(2048)`.
- Downgrade had a bug in the first version (only dropped the
  halfvec, didn't re-add the vector column, leaving the schema
  inconsistent with C1). Fixed: downgrade now does
  `drop_column → add_column Vector(2048)`. Round-trip verified
  clean after the fix.

- Missing-var behavior locked: deny via cast error

- **Real finding during verification:** `finagent` is the superuser
  Postgres bootstrapped via `POSTGRES_USER`, so it has
  `rolsuper=t` AND `rolbypassrls=t`. Superusers bypass RLS
  regardless of policy. Probe 2 (set `app.manager_id='2'` and
  query as `finagent`) returned all 3 rows instead of just Alice's
  2 — looked like RLS was broken until I checked `pg_roles`.
  Created a temporary `rls_test` role (`NOSUPERUSER NOBYPASSRLS`)
  and re-ran probes:
  - as `finagent` (superuser): sees all 3 ✓
  - as `rls_test` with `app.manager_id='2'`: sees Alice's 2 ✓
  - as `rls_test` with `app.manager_id` unset: query errors with
    `invalid input syntax for type integer: ""` ✓
- `rls_test` role left in the DB (test role, low privilege,
  harmless). Can be dropped later.

## Architectural decisions made today

1. **`embedding` column type = `halfvec(2048)`, not `vector(2048)`** —
   driven by pgvector's HNSW 2000-dim cap on `vector`. Half-precision
   is fine for cosine retrieval; storage halves. Tradeoff: writes
   have a tiny precision-loss step, negligible at this scale.
2. **HNSW with `vector_cosine_ops` (would have been) →
   `halfvec_cosine_ops`** — operator class must match the column
   type. Default parameters (`m=16`, `ef_construction=64`); logged
   a follow-up to revisit when data exists.
3. **RLS on `morning_notes` only** for D1 (not all six tables
   as originally scoped) — manageable in one session; the remaining
   five tables become a follow-up issue when their policy shape
   is clearer.
4. **Single migration for D1, no role split yet** — the migration
   creates the policy but doesn't add `finagent_app` role. App
   code still connects as `finagent` (superuser, bypasses RLS).
   Two-role split lives in a follow-up issue so we don't break
   the app without app code to test against.
5. **DENY by default on missing `app.manager_id`** — empty-string
   cast error surfaces at query time. Forces every connection
   to set the var. Insecure default would be `USING (true)` which
   returns nothing — chosen "deny loud" instead.
