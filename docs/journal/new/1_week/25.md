## Decisions made

- **Explicit manager_id WHERE clause alongside RLS** — RLS policy exists but wasn't filtering in test environment (likely transaction/session scope). Added `WHERE MorningNote.manager_id == manager_id` as safety net matching list endpoint pattern.
- **Response as dict, not Pydantic model** — Matches existing `list_morning_notes` pattern. Pydantic model deferred; noted in PR for future.
- **`selectinload` over `joinedload`** — Three to-one relationships; `selectinload` avoids Cartesian product from multiple LEFT JOINs. 4 small queries vs 1 large joined query.
- **404 for RLS rejection (not 403)** — Per ADR-012: "404 if note not found or RLS filters out". Client cannot distinguish between "doesn't exist" and "not yours".
- **`str, Enum` status field** — `note.status` returns string directly; calling `.value` on string fails. Removed `.value` in endpoint.

## Decisions worth flagging

- **RLS policy effectiveness in tests** — Policy exists in migrations but `SET LOCAL` may not propagate to `selectinload` subqueries in async session. Explicit WHERE clause is the pragmatic fix; revisit if RLS enforcement becomes critical for compliance.
- **`flags` field returns `{}` not `[]`** — Model default is `server_default=text("'{}'::jsonb")`. Test accepts both; consider normalizing to empty list in endpoint or changing model default.
- **Pydantic response model deferred** — Frontend will need TypeScript types; generating from Pydantic would be cleaner. Track for Phase 2.
- **`data_freshness` datetime serialization** — FastAPI/Pydantic auto-serializes datetime to ISO strings. Verified works but not explicitly tested.
