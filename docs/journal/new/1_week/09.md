### The repo path-divergence discovery

Then came the turn that ate the rest of the session. I tried to merge
`feature/issue-04b-logging-middleware` into the post-revert main. The
merge succeeded silently but the working tree didn't gain the #04b
files. `ls finagent/app/middleware/` returned nothing; `git ls-tree`
for the merge commit returned empty too.

Deeper digging surfaced a layout mismatch that had been hiding the
whole session:

- **Upstream `main` tree:** `.gitignore`, `README.md`, `finagent/{...}`
  — files at `finagent/app/`, `finagent/tests/`, etc.
- **Local working tree on entry:** `finagent/{...}` — same shape as
  upstream, but git's worktree root was the *parent* of `finagent/`,
  not `finagent/` itself.
- **Recent upstream commits** (`e698511` #04b feature, `8208dec` merge,
  `70d71a3` revert): `app/`, `tests/`, etc. — files at root, NO
  `finagent/` prefix.

The recent commits had been authored from a clone where files were at
root. The current local working tree had files under `finagent/`. Git
saw them as different paths. My Reads/Edits/Globs were hitting the
local working tree, but the git operations I thought I was doing
operated on a tree that didn't match the filesystem.

The session I thought I was running (verifying #04a, merging PRs,
testing endpoints) was partly running on a phantom tree.
