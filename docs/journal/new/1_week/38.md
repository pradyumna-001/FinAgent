## Decisions made

- **Guard condition is `snap.next` non-empty, not "checkpoint exists."** A completed run has checkpoints but nothing pending; only `next` separates "waiting for a decision" from "ghost or finished."
- **Resume-failure recovery = delete the Redis decision key + flag + let the human re-press (Option B), NOT inline retry (A).** Reasoning: `ainvoke` re-executes from the last checkpoint after a mid-graph raise — any side-effecting node that succeeded before the failure could fire twice (second Telegram keyboard, double note write). The human is the gate anyway; make the human the retry.
- **Resume before `answer_callback_query`.** The toast must reflect reality: "registrado" only after the resume actually ran.
- **Ghost Redis key left in place** on the guard-refuse path — it dedupes future presses of the dead button, and TTL (24h) cleans it.
- **`resume_value` derived from `action`, not `decided`** — the wire (the finger's click) is the single source of truth.
- **Inline `redis.delete(decision_key(...))`, not a `delete_decision` helper** — `decision_key` keeps key-format knowledge in `decisions.py`; minimal surface.
- **The `async with` rule, generalized:** a context manager is correct exactly when nothing it manages outlives the block. Worker's trap was a module-global outliving the CM; the poller's graph is a local that dies with the coroutine — no trap possible.
