#### Phase 4: Fix CI Integration Test Failures
- **Root causes fixed:**
  1. **Event loop conflicts** — pytest-asyncio creates new event loop per test; session-scoped engine tied to first test's loop → "Future attached to different loop" errors
  2. **Global `SessionLocal` patching** — `consolidate_node` imported `SessionLocal` at module load; test patches didn't affect it
  3. **FK constraint violations** — Cleanup deleted companies before `portfolio_holdings` (wrong order)
  4. **Global state leakage** — Integration tests patched global `SessionLocal` but didn't restore; unit tests failed when run after integration tests
  5. **Mock targeting** — Patches targeted service modules (`app.services.llm.summarize`) instead of agent modules where functions are used (`app.agents.risk.summarize`)

## Decisions made

- **Per-test self-contained engines** — Each test creates its own engine in its own event loop; no shared state, no cross-test leakage
- **Runtime `SessionLocal` access** — `consolidate_node` uses `_get_session_local()` at call time so test patches work
- **Proper cleanup order** — `PortfolioHolding` → `Portfolio` → `Company` → `Manager` (children first)
- **Mock at point of use** — Patch where functions are called (`app.agents.risk.summarize`), not where defined (`app.services.llm.summarize`)
- **Standalone test runner pattern** — Works on Windows (bypasses testcontainer); uses existing PostgreSQL container directly
- **Removed `asyncio_test_loop_scope`** — Not supported in pytest-asyncio 1.4.1; per-test engines handle event loops naturally

## Decisions worth flagging

- **Testcontainer on Windows** — Still flaky; standalone runner pattern is reliable workaround
- **`consolidate_node` runtime import** — Minor indirection but enables test isolation; acceptable trade-off
- **Per-test engine overhead** — Slightly slower but eliminates flaky CI; acceptable for reliability
- **Mock proliferation in graph tests** — 7 patches per test; could use fixture but explicit is clearer for debugging
