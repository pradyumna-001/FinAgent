## Decisions made

- **Dual DATABASE_URL pattern** — Separates migration-time (superuser) from runtime (least-privilege `finagent_app`). Enforces principle of least privilege at infrastructure level.
- **NOSUPERUSER NOBYPASSRLS** — Explicitly prevents finagent_app from bypassing RLS or gaining superuser powers.
- **REINDEX CONCURRENTLY** — PostgreSQL 12+ feature; avoids blocking reads/writes during HNSW rebuild.
- **pgvector/pgvector:pg16 service container** — Includes pgvector + Apache AGE pre-installed; matches production RDS setup.
- **alembic upgrade heads (plural)** — Migration history has multiple heads (app role split + hnsw reindex were parallel branches). Singular `head` fails.
- **Single workflow file** — Keeps unit + integration in one `ci.yml` for simplicity; can split later if needed.

## Decisions worth flagging

- **App role password not set in migration** — Created without password; test fixture sets `ALTER ROLE ... WITH PASSWORD`. Production needs secret injection (future infra task).
- **HNSW drift thresholds are conservative defaults** — idx_scan ≥ 1000, rows ≥ 10000, ratio ≥ 0.1. Should be tuned based on production query patterns.
- **No automatic cron for reindex** — Script designed for external invocation (cron, Celery Beat, systemd). Deployment task.
- **Docker layer caching not configured** — GitHub Actions service containers don't persist; caching would need self-hosted runners or build-push-action.
- **RLS on remaining 5 tables (#03a) still pending** — Managers, companies, portfolios, portfolio_holdings, recommendations need policies.
