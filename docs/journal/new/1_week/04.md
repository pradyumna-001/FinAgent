### Chunk A — additive columns on MorningNote
- `status: Mapped[MorningNoteStatus]` with `String(16)` + named
  `CheckConstraint("status IN (...)", name="ck_morning_notes_status")`
  and `server_default=MorningNoteStatus.PENDING.value`.
- Three JSONB columns: `confidence_scores`, `data_freshness`, `flags`,
  each with `server_default=text("'{}'::jsonb")` (the `text()` wrap is
  required because bare strings get bound as parameters and Postgres
  has no implicit text→jsonb cast at DDL time).
- Two new FK columns: `manager_id` (FK managers.id, indexed, NOT NULL),
  `company_id` (FK companies.id, indexed, NOT NULL). The denormalization
  is for RLS — `manager_id` on the row is what the policy compares
  against `current_setting('app.manager_id')::int` without a subquery.
- New `class MorningNoteStatus(str, Enum)` in `app/db/models.py`. The
  `(str, Enum)` parent is intentional: bare `Enum` would break
  equality (`PENDING == "pending"` False) AND string serialization
  (`f"{status}"` would render the class name, not the value).
- JSONB import is dialect-specific:
  `from sqlalchemy.dialects.postgresql import JSONB`. The generic
  `JSON` compiles to `jsonb` on Postgres anyway, but the explicit
  dialect import means the code fails loudly if someone ever tries to
  run it on MySQL — the column genuinely requires JSONB semantics.

## Architectural decisions made today

1. **`MorningNoteStatus` as `(str, Enum)`** (vs `Enum` alone) — defended
   on the chat; the `str` parent fixes both equality and string
   serialization.
2. **`String(16)` + named CHECK constraint for `status`** (vs native PG
   `Enum`) — same call you made for `action` in PR #30, but stronger
   here because status is a state machine with exactly four values.
   Easier to evolve than native Enum (drop+recreate CHECK), still
   DB-enforced.
3. **Hand-written migration over autogenerate** — first migration
   always. Saves the autogenerate-cleanup dance and makes the DDL
   reviewable. Autogenerate is the right tool for *catching drift
   between model and DB*, not for emitting the first migration.
4. **`extra="ignore"` in SettingsConfigDict** — Settings declares
   what *this module reads*, not what the project will ever need.
   Lazy declaration per feature.
