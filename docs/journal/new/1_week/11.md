## Decisions made

- **Server-mints both UUIDs (Decision A1)** — The server creates the morning_notes row eventually (#19), so it owns the namespace. Client-supplied IDs would let two clients collide with no defense.
- **SSE event payload is a single flat `data:` line (Decision B1)** — No `event:` field, no taxonomy. YAGNI for the multi-event case; richer shapes land in #21.
- **Local import of `_PIPELINE_REGISTRY` inside `trigger_pipeline`** — Defensive placement against a future circular import. If `app/services/pipeline.py` ever adds a top-level `from app.api.routes.pipeline import _PIPELINE_REGISTRY`, the cycle would break module loading. Local import defers the edge to call-time, when both modules are fully loaded.
- **Pass-through params in the stub** — `run_pipeline_stub` takes IDs as args, does not generate or look them up. The route is the boundary that owns identity; the stub carries the identity it's handed. Computing here would re-mint and lose the link to the 202 response.
- **Tests bypass DB fixtures** — The trigger route and the stream route don't touch Postgres today. The `bound_engine` / `migrated_db_url` chain from `test_morning_notes.py` would add Docker boot + migration time without proving anything. Plain async HTTP tests are sufficient.
- **In-memory `_PIPELINE_REGISTRY` as a stub seam** — Today's registry is a module-level dict populated by the trigger route and read by the stream route. #19 replaces it with a real DB lookup. Keeping it in-memory lets #04c ship and #19 land as a swap, not a redesign.

## Decisions worth flagging

- **404 handler swallows the traceback** — The `MorningNoteNotFound` exception handler converts the exception to a 404 JSON response but does not log. The operator sees the access-log line (`GET /morning-notes/X/stream → 404`) but not the exception itself. When #19 lands and real clients hit stale note_ids, an operator debugging needs `logger.warning("morning note not found: %s", exc.args[0])` inside the handler. Open follow-up.
- **`X-Pipeline-Run-Id` header is set, but `X-Morning-Note-Id` is not** — The middleware (from #04b) accepts both correlation headers. The trigger route echoes only `X-Pipeline-Run-Id`. If the SSE stream ever logs a 404, the access log will have the run_id but not the note_id. Consider echoing both for symmetry. Open follow-up.
- **`test_trigger_returns_202_with_ids` initially had `"manager-id": 1` in the JSON body** — The header name leaked into the body, pydantic 422'd. Caught at the verify step, fixed in the test file. Not a code bug; a test-fixture typo. Worth noting because it was the kind of muscle-memory slip that's easy to miss in chunked review.

## What I learned

Two things marked me this issue:

1. **Local imports dodge circular-import failures.** Putting `from app.services.pipeline import _PIPELINE_REGISTRY` inside `trigger_pipeline` (not at the top of the file) means Python doesn't hit the cycle during module loading. It's cool because we defer the edge to call-time, when both modules are fully loaded. I didn't fully get this until the third Socratic question sharpened it for me — I'd been thinking about *current* cycles instead of *future* cycles a refactor could create.

2. **`!r` format specifier for safe JSON embedding.** I never saw `!r` before. It calls `repr()` on the value, which escapes newlines and quotes. Without it, a malformed note_id containing `\n` would break the JSON response body. Now I get why FastAPI's default error responses use `repr()` on untrusted strings.
