### Chunk C4 — `env.py` reads `DATABASE_URL` from `os.environ` directly

`env.py` was importing `from app.config import settings` and calling
`settings.DATABASE_URL`. Pydantic-settings freezes its values at
module-import time. The `migrated_db_url` fixture relied on a subtle
import-order property: `os.environ` is mutated *before* `command.upgrade`
triggers `env.py`'s first import, so `Settings()` constructs against the
overridden env. Worked in practice; would have silently broken the
moment any test or fixture imported `app.config` ahead of the fixture.

Decision: **migrations should not depend on the app's settings module.**
Replaced both `settings.DATABASE_URL` references (online and offline
modes) with `os.environ["DATABASE_URL"]`. Missing-var now raises
`KeyError` — fail-loud, which matches our RLS "deny loud" posture.

Real bug found: `run_migrations_offline` was also calling
`settings.DATABASE_URL` and would have crashed on any future
`alembic upgrade --sql` run. Fixed in the same chunk; both call sites
read from `os.environ` now.

### Typing fix — `fetch_scalar` returns `Any`

Mypy flagged six errors in `test_migration_smoke.py`: `assert "..." in composite`
where `composite: object`. `fetch_scalar` runs arbitrary SQL where the
return type genuinely varies (int from `count(*)`, text from
`format_type`, etc.). `Any` is the honest annotation; alternatives
(`cast(str, ...)` at every site, or splitting into typed helpers)
would have hidden the truth. Separate commit so a future reviewer can
bisect "added the test" from "fixed the helper's type."

## Architectural decisions made today

1. **`env.py` does not import `app.config`** — migrations are a
   deployment tool, not an app tool. They read `DATABASE_URL` from
   `os.environ` directly. Removes a fragile import-order dependency
   on Pydantic-settings' freezing behavior.
2. **Per-migration probe tests live alongside the smoke** — each
   migration gets one test function. Test name maps to migration
   signature artifact. Future migration breaks → targeted failure
   name.
3. **Behavioral RLS test belongs in E, not deferred** — the journal
   had it as a follow-up because the role split was deferred. But
   the behavioral test only needs a temporary role inside the
   ephemeral container; it does not require the app's role split.
   So we landed E5 without waiting on the role-split follow-up.
4. **`DROP OWNED BY CASCADE` is the teardown idiom** for any role
   in a test fixture, not `REVOKE` per grant. Survives future grant
   additions without test changes.
5. **`fetch_scalar` returns `Any`** — not `object`, not per-call
   casts. Honest annotation for genuinely-dynamic SQL.
