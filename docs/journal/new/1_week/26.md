## Decisions made

- **Return `None` from `decode_access_token` on error** — Initially tried raising `InvalidTokenError`, but handling in `get_current_manager` with try/except is cleaner and matches existing pattern of converting to HTTPException
- **`get_current_manager` uses `manager_id` claim** — Login endpoint encodes `{"sub": email, "manager_id": manager.id}`; dependency checks for `manager_id` in payload
- **`HTTPBearer(auto_error=False)`** — Allows custom 401 messages ("Not authenticated" vs "Invalid token" vs "Manager not found") instead of generic FastAPI 403
- **Test passwords in fixture** — Hardcoded `alice123` / `bob123` hashed via `hash_password()` in conftest.py setup; avoids needing a seed script
- **401 for auth failures, 404 for RLS isolation** — Valid token but wrong manager → 404 (matches ADR-012: "404 if note not found or RLS filters out")

## Decisions worth flagging

- **`decode_access_token` returns `dict | None`** — Current implementation catches `JWTError` and returns `None`. `get_current_manager` converts to 401. Consider custom exception if more granular error handling needed later.
- **No token refresh yet** — ADR-017 plans hybrid (JWT + refresh cookie) for Phase 3/4. Current 30-min expiry requires re-login.
- **`sub` claim is email, not user ID** — Login uses `sub: email`, `manager_id: id`. Dependency uses `manager_id`. Slight inconsistency; could standardize.
- **SSE stream ownership check** — Added DB query before subscribing to verify note belongs to manager. Consider caching or moving to middleware if performance becomes issue.
- **Test fixture creates managers with known passwords** — If fixture changes, tests break. Consider separate test data setup.
