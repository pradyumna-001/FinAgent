## Decisions made

- **Duplicate prevention at app level** — Defined duplicate as same `(morning_note_id, manager_id, action, justification, comment)`. Chose application-level check over DB unique constraint because managers can post multiple feedbacks over time (e.g., buy Monday, sell Tuesday); only identical submissions are blocked. NULL handling in `comment` required explicit `IS NULL` check.
- **`min_length=10` on justification** — Per ADR-011 acceptance criteria. Added after first PR draft; this was a real gap caught by the issue spec.
- **Router registration in main.py** — Added feedback router to `app/main.py` (was missing initially — caused 404 on tests).
- **Manager-id validation `manager_id <= 0`** — Rejects 0 and negatives. Protects f-string interpolation on line 28 (SQL injection safety via type system + range check).
- **`manager-id` header alias** — Used `Header(None, alias="manager-id")` matching existing pattern in `morning_notes.py`.

## Decisions worth flagging

- **Pre-existing mypy error** — `tests/unit/test_dataflag.py:39` has a type error that CI doesn't catch because `mypy app` excludes `tests/`. Open issue to evaluate whether `tests/` should be in mypy scope.
- **Frontend integration deferred** — `useFeedback` hook + `FeedbackModal` to be built in Phase 2.
- **Feedback analytics fields deferred** — `confidence_delta`, `tags`, `original_*` snapshots to be added in Phase 3 per ADR-011.
- **`bound_engine` fixture migration** — Moved from `test_morning_notes.py` to `conftest.py`. Future integration tests should add fixtures here, not locally.
- **Duplicate prevention is idempotency guard, not uniqueness** — Same input + same state = 409. Different action or comment = 201.
